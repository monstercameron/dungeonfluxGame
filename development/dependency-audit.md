# Experimental fixture dependency audit

This records a partial G01 prerequisite for the four-crate S00 transport fixture at source revision `822ffc4992b34ab548a47cf91efad845ca50c716`. It is descriptive dependency and license evidence. It does not approve a legal admission policy, establish commercial fulfillment, or qualify all of G01.

Cargo 1.98.1 and rustc 1.98.1 ran on `aarch64-apple-darwin`. The checked-in toolchain pins Rust 1.98.1 and `wasm32-unknown-unknown`. The source-bound locked offline metadata commands resolved 140 package identities for native and 141 for wasm; their union contains 150 identities. The four workspace crates are `df-protocol`, `df-rpc-bridge`, `df-observe`, and `df-tools`. The fifth local path package visible to Cargo is vendored `h2 0.4.19`, excluded from workspace membership but injected by the `[patch.crates-io]` entry.

`metadata/native.json` and `metadata/wasm.json` retain complete Cargo metadata outputs. `packages.json` records package IDs, declared SPDX-like license expressions exactly as Cargo reports them, repository metadata, target feature sets, dependency edges and their declared kinds/target selectors. It records the exact license expressions Cargo returned, hashes for available top-level license/copying/notice files and manifests, and Cargo.lock archive checksums where present. These are provenance and attribution evidence, not license-expression validation or an assertion that each package's complete obligations have been met. Eighteen package records have no detected top-level license/notice file; the four workspace path packages and vendored h2 have no Cargo.lock archive checksum. Its declared MIT expression, vendored `LICENSE` SHA-256 `b21623012e6c453d944b0342c515b631cfcbf30704c2621b291526b69c10724d`, manifest hash, and repository URL are retained. The vendored attribution must remain with any reuse. Extracted source-tree hashes, missing license files, and fulfillment details remain unresolved; recorded lockfile checksums were not independently checked against crate archives.

The captured `cargo tree` outputs show native-only `axum` and transport dependencies, wasm-only browser bindings and WebSocket APIs, `df-protocol` build dependencies, proc-macro nodes, enabled features, and `df-rpc-bridge` native development dependencies. Cargo's resolver metadata and tree are approximate build graphs. They do not prove which code was linked or called in a produced executable, nor browser runtime behavior. No native/WASM binary was built for this audit. Browser native-I/O exclusion still needs actual artifact and boundary evidence; native I/O qualification remains unresolved.

Run `python3 development/dependency-audit.py` from any directory to verify the fixed, bounded set of source and evidence inputs. It reads only named paths beneath this checkout, rejects missing, non-regular, oversized, malformed, stale, or identity-incomplete inputs, and does not accept input path arguments. `development/dependency-audit/report.json` binds every pinned input hash and the exact target/package identity sets; the verifier also checks its fixed SHA-256 so an edited report cannot bless altered inputs. Captured metadata preserves the assigned worktree's absolute paths for provenance; the verifier checks source files against the pinned current checkout bytes and checks graph identities rather than treating those absolute paths as current source.

The exact bounded command invocations, outputs, toolchain identity, and their hashes are retained in `../evidence/dependency-g01/worker/commands/`. Cargo ran through `development/build-fixture.sh cargo` with the assigned shared artifact/cache roots, `--locked`, and `--offline`. One initial `cargo tree` attempt used unsupported `proc-macro` as an edge kind and exited 1; the corrected `--edges all` and normal/build/features commands succeeded. That failed invocation is retained as a negative command outcome. No source manifests, Rust, protobuf, build scripts, or toolchain files were edited. This audit does not claim the full project gates have passed.

The verifier checks the report's fixed SHA-256 before parsing any report fields. Negative metadata/package fixtures use a temporary copy of the verifier pinned to each deliberately mutated fixture report, so they exercise the underlying bounded parsers and identity checks without changing the submitted tool or report.
